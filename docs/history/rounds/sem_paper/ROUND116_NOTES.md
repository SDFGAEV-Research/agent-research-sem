# Round 116 — retire the runtime-control composition boundary

## Decision

The historical `platform/composition/runtime_control` directory was not a
runtime owner. It mixed two unrelated cross-system assemblies:

- operation execution bound to observability and reliability projections;
- release-consumer quiescence bound to session, recovery-lease, and service
  observations.

Keeping either assembly under a runtime-control-named directory would preserve a
false architectural authority and make future replacement harder.

## Migration

- Moved `build_operation_executor` to
  `research_platform.platform.composition.operation`, the explicit platform
  composition seam for the cross-system execution/observation/failure binding.
- Moved release-consumer adapters to the explicit cross-system composition
  module `research_platform.platform.composition.release_quiescence`.
- Moved the proof join to
  `research_platform.governance.release.composition.retirement` and renamed the
  class to `ReleaseQuiescenceVerifier` to reflect its release-wide ownership.
- Rewired all production tests and the release source invariant to the target
  ownership.
- Removed stale import-graph, recovery, effect, and observability guardrails
  that named the retired composition path.
- Physically deleted the old Python modules and generated bytecode directory;
  no compatibility import or forwarding module remains.

## Boundary rule

The event spine remains observation-only. `build_operation_executor` receives
explicit failure/event ports and returns a directly usable executor; it does
not discover services through a bus. Release retirement receives explicit
consumer probes and produces one evidence-bound proof; it does not own any
session, service, or recovery backend.
